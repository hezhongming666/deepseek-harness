# 工业自动化 AI Agent 闭环架构 v1.1 —— 实现符合性报告

> 审计对象：设计稿 v1.1（`工业自动化AI-Agent闭环架构-v1.1.docx` 的 Markdown 孪生版，575 行）对照 dsh 工业能力族实现（版本基线：提交 `771d09ab48`，7 个包 + Openness 桥 + 示例，全部经真实 TIA Portal V21 验证）。
> 审计日期：2026-09-05；同日修订（第二轮：P0 持久化与 P1 学习管线对齐）。本报告是对账基线，随实现迭代更新。

## 结论

**深度忠实、广度留白。** 设计的"骨架"——验证即门禁、确定性裁决、六道恒人工闸门、A0–A3 分级、内环/升级/学习三闭环、三级影响分析、知识冷启动——全部按原样落地且有真实厂商编译背书。第二轮已消除首轮审计的最大偏差：§5.5 状态持久化（四类状态落盘与启动恢复 + 审计包导出）与 §4.3 学习管线自动沉淀均已实现。剩余缺口集中在设计明示为后续的广度（电气/HMI/仿真、多项目调度、模型治理），且每处留白均符合设计红线"不具备自动化接口的环节宁可人工也不可假自动"。

## 一、对齐（核心机制零偏差）

| 设计条款 | 实现事实 |
|---|---|
| §1.3 验证即门禁、失败要响亮 | 阶段流转先跑绑定验证器；验证器是输入的纯函数；未知种类抛错、外部通道全路径失败关闭，无静默降级 |
| §2.3 控制程序验证域 | 本地语法/Lint（命名、未用变量、未定义引用）+ 真实 TIA Openness 导入编译（活桥实测） |
| §3.10 编排器治理约束 | 编排器结构性无权批准闸门；DAG 状态机、模板实例化、项目 id 隔离 |
| §4.1 内闭环 | 重试预算默认 3 次，失败以验证报告为修复输入 |
| §4.2 升级包 | 任务上下文、当前产物、验证证据、失败摘要、候选方案逐一对应 |
| §4.4 追溯与三级影响 | direct/indirect/potential 与设计的直接/间接/潜在定义逐字一致；需求矩阵自动维护覆盖 |
| §5.1 自动化分级 | A0–A3 四级，默认 A1；危险闸门恒人工，不随等级放开 |
| §5.2 六道强制闸门 | 需求基线、设计评审、SIL 终审、首次上电、验收签字、在线变更逐一对上；外加 release-review 项目闸门（合计 7，符合"6–8"预算） |
| §6.2 知识冷启动 | 模板 ≥20、案例 ≥30 默认最小值；低于规模时检索带 degraded 显式标示；入库人工审核（pending-review，严于设计的"抽检 ≥20%"） |
| §6.2 检索带出处 | 知识条目强制 source+version，检索结果带出处 |
| 红线 | SIL3+ 不自动生成；无自动化接口的仿真阶段由人工 release-review 承接，不放假验证器 |

## 二、有意偏差（已记录于 Agent Note，不是疏漏）

1. **九个专职 Agent → 六阶段 DAG + 单一模型会话。** 设计 L3 列出 9 个专业 Agent；实现以 conveyor-line 模板的六个阶段承载（电气/HMI/文档并入阶段，运维未入），"Agent"由模型会话加工具面承担。设计 §3 允许实现差异，但多 Agent 人格化（双 Agent 交叉评审等）未实现。
2. **方言接缝 `vendorSource`。** 设计未规定本地检查方言与厂商 SCL 方言的处理；实现以显式第二源承接（本地读 `text`、tia-compile 读 `vendorSource`），并明确拒绝"翻译器"方案。
3. **内环"诊断 Agent"未拆独立角色。** 设计中诊断 Agent 分析错误；实现中诊断=模型读验证报告自行修复。机制等价，角色未拆。
4. **整软件编译的运维约束。** 实测发现桥编译整个 PLC 软件，草稿项目内任何其他坏块都会污染每次验证；设计未提此约束，已写入包 README 与 Agent Note。

## 四、已消除偏差（第二轮修订）

1. **§5.5 状态持久化（首轮 P0）。** 项目阶段机、追溯图、闸门请求与裁决、知识条目四类状态各增 `dataDir` 落盘：每次已提交变更写一份原子版本化 JSON 快照（`dsh-atomic-write` 的 `readJsonSnapshot`/`writeJsonSnapshot`），加载期同步恢复，畸形/版本不符快照响亮失败；写入失败抛错且内存提交保留（快照非 fsync 日志）。闸门定义与自动放行规则是注册效果（代码），不落盘、启动时重新注册。示例冒烟新增第三次装配验证跨启动恢复（23 项检查全过）。
2. **§5.4 审计包导出（首轮 P0 的一部分）。** `exportAudit(projectId)` 汇集每个阶段的机器状态与绑定闸门的完整请求-裁决历史；`ia_project` 工具新增 `export` 动作。
3. **§4.3 学习管线（首轮 P1）。** 提交在同一次内环运行中先失败后通过时，自动把失败-修复对沉淀为 `pending-review` 案例（可选的 `ctx.iaKnowledge`）；沉淀库的重复拒绝即去重闸门，任何沉淀库故障都不阻断已通过的阶段。

## 五、下一步迭代基线

1. **P1：行为验证。** 装 PLCSIM（或等价仿真目标），把桥的 online 动作接入 simulation 阶段，起保停真值表一类用例自动执行；电气/HMI 依"有自动化接口才纳入"原则选型接入。
2. 其余 P2/P3 随证据积累逐个纳入；主备与异地备份属部署层，不进代码包。危险闸门与"无接口即人工"红线在任何阶段不放开。
