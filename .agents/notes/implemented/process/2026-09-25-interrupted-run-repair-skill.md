# Agent Note: Interrupted-run repair as a skill

Status: implemented

English | [中文](2026-09-25-interrupted-run-repair-skill.zh.md)

## Problem

Long-running jobs that append to or rewrite on-disk artifacts fail after an interruption in two opposite directions, and a plain re-run handles neither. Residue that the reader cannot parse breaks every retry on the same bytes, so the artifact never completes; residue that the reader tolerates is accepted as success, so a truncated record, a zero-byte completion marker, or a JSON document silently reset to empty survives re-running and hides the damage.

The knowledge needed to tell these apart — which byte pattern leaves a file unreadable, which one fools a completion check, and which repairs discard information — was per-project, discovered by reading a producer's code during a review of an external pipeline: a scheduled tick that appends samples, an independent close task that aggregates them, a single-writer lock, and a marker file whose existence alone means "finished". Nothing in the repository turned that reading into a procedure an agent can run.

## Decision

`.agents/skills/dsh-interrupted-run-repair/` ships the procedure and three stdlib-only Python tools: `scripts/repair_interrupted_run.py` with the subcommands `detect` (read-only), `repair`, `verify`, and `selftest`; `scripts/audit_interruption_hazards.py`, which scans source for the code that keeps producing the residue; and `scripts/hazard_guard.py`, which compares a scan against a stored baseline and alarms only on new findings. The repair tool's input is a **run contract** — a JSON list of the artifacts a run claims to produce, each with a `kind` (`jsonl`, `csv`, `json`, `lock`, `text`), an optional `unique_key` for duplicate detection, `columns` for CSV field counts, `role: completion-marker` for the artifact whose existence means the run finished, `required` for artifacts whose absence is incompleteness, and `lease_seconds` for lock age. An entry names either a `path` or a `glob` pattern expanded against the root at load time, so a daily chain's contract covers days that do not exist yet; a strict pattern such as `day_????-??-??.jsonl` keeps a same-prefix registration file out. Contract data names files; it never carries a command.

The same contract doubles as the audit's **artifact graph**. With `--contract`, the scanner escalates a truncate-and-write in any file that references a declared artifact — catching writers whose readers live in another file, which the same-file rule cannot see — and suppresses advisories far from declared artifacts. On a 284-file pipeline with 16 declared artifacts that moved `medium` from 35 to 61 while cutting `advisory` from 605 to 69, so the contract raises recall and lowers noise at once. The guard's identity is `pattern + severity + relative path + normalized evidence line + occurrence index`: no line number, because line drift would flood every run with fake additions; an occurrence index, so an added duplicate is still seen; and severity, so an advisory that escalates to `medium` counts as the regression it is. The guard binds no channel and no exit-code convention — `--notify-cmd` gets the alert body on stdin, `--min-severity` sets the threshold, and `--exit-code-new` lets a caller keep its scheduler's own code — because those are deployment choices, not detection logic. A scan that reaches no file exits 2 instead of reporting clean, and `--update-baseline` refuses to write an empty baseline: a directory renamed out from under the guard would otherwise keep reporting clean, and an empty baseline would erase the identities that make a later regression visible. `--allow-empty` is the explicit opt-in.

The audit tool matches six shapes with the AST rather than with regular expressions: an appended file parsed whole, a handler that substitutes an empty document for a corrupt one, a truncate-and-write, an `exists()` completion test, a read-then-append cycle with no lock in the enclosing function, and a `read_text()` without `errors=`. Precision is the design constraint, and it cost three tightenings during development: escalation requires the **same file** to read the path back, because a name like `OUT` is a different artifact in every script; a silent reset requires a persisted-input read in the `try` body, because defaulting a value after a failed RPC is a different failure mode; and a handler that records what failed is disclosure rather than a reset. Each `high` is verified by reading the code before it is reported.

Findings carry one of three kinds. **corruption** blocks or falsifies a re-run, **incompleteness** only a producer re-run clears, and **advisory** is reported for judgement and never fails a run. Repair runs at the narrowest tier that clears the corruption: tier 1 terminates a record whose terminating newline was lost, truncates an interrupted tail, quarantines a wholly unusable file, and clears a lock whose holder is provably gone; tier 2 (`--quarantine-lines`) keeps parseable records and archives the rest; tier 3 (`--dedup`) keeps the first record per `unique_key`. Every action writes an archive beside the artifact and reports its path.

Agent Note invariants: containment (an artifact path resolving outside `--root` is a contract error, exit 2), no invented content, idempotent repair, silent dry runs, coverage accounting (every report states how many declared artifacts were inspected, present, and absent, so a clean verdict is falsifiable rather than silence), and no clearing of a lock whose holder is alive — not even past its lease — without `--force-live-lock`. `--rerun "CMD"` records the producer's command, exit code, and output tail in the same report as the repair, so one report carries the whole loop; that command comes from the operator's command line, so a stale contract cannot trigger execution. Windows and POSIX pid liveness differ, and the Windows path reads the exit code through `ctypes`.

Residue classes the tool deliberately does not repair — lost updates from two concurrent writers, a reader that swallows corruption and resets state, truncated binary formats, and reconstructing dropped records — are recorded with their rationale in `references/cases.md`, together with the real case behind each fixture.

## Verification

`selftest` builds 18 cases in a temporary directory and asserts the whole loop for each one: detect names the residue, repair clears it, the producer re-runs, and verify reports an intact complete run. Positive cases cover a partial last line, a complete record missing its newline, concatenated records, a truncated CSV row, an empty completion marker, a truncated JSON document, a stale lock, duplicate records, a multi-byte tail cut mid-character, and a glob contract spanning several days. Incompleteness cases cover a required glob that matches nothing. Negative controls must stay untouched: clean artifacts, a lock whose holder is alive, and an orphan temp file beside an intact target. Guards cover repair idempotence, dry-run silence with an exit code that reflects what the requested flags can actually clear, and rejection of a contract path that escapes the root.

The self-test is the acceptance and runs on demand; it is not wired into a `pnpm` gate, which would put a Python runtime requirement into the static gate set. The skill's Markdown is covered by the documentation gates. The clean-baseline case also asserts the report's coverage counts, so a run that inspected nothing cannot pass as clean. `audit_interruption_hazards.py --selftest` asserts the mirror image for the scanner: every hazard pattern fires on its fixture, its safe twin stays quiet, a contract escalates a declared-artifact writer, and advisories far from any declared artifact are suppressed. `hazard_guard.py --selftest` asserts the guard's own contract: baseline writes, known hazards stay quiet, a new hazard reaches the caller's exit code with the alert body on the notifier's stdin, a line shift is not new, an added duplicate is, the severity threshold is honoured, and a severity escalation to a declared artifact is reported — the last one after the identity was corrected to include severity, which the self-test caught. Both scanners also assert the loud-failure path: a target that does not exist, or a scan that reaches no Python file, exits 2 rather than reporting a clean audit.

## Alternatives considered

**Fix each producer instead.** Lost on immediacy but kept as the right answer for one residue class: guarding a reader's parse, replacing `truncate` + `write` with an atomic rename, and failing loud instead of resetting state on a corrupt input all prevent the damage, and this skill cannot repair the producer. It does not help an already-interrupted run, and it must be repeated in every project; the skill states which defects stay the producer's.

**Repair by re-running the producer alone.** Lost because a re-run cannot detect the residue that breaks it, and cannot see the residue a reader swallows: the run looks successful while the artifact stays wrong. The tool's job is to make the re-run's starting state trustworthy, which is why the contract and the detect phase exist.

**A package with a verifier and CI tests.** Lost because the consumers are operator workflows over other projects' files, not the harness runtime. The repository's package gates — per-file coverage, invariants, catalogs — would govern a tool that never runs in the product, and the skill form keeps it callable from any workspace.

**Line-level repair as the default.** Lost because dropping a record is a semantic decision: the tiers make that loss explicit, opt-in, and disclosed in the report rather than implicit in a clean verdict.

**Third-party dependencies.** Lost because stdlib-only keeps the script runnable on any host the agent reaches, including ones with no Python packages installed; `psutil` and `jsonschema` would each buy a little convenience at the cost of an install step on a machine that cannot be modified.

## Consequences

Bought: one deterministic procedure and evidence trail for the interrupted-run case, with the failure analysis from an external pipeline captured as a runnable acceptance instead of prose; a repair policy that never silently drops bytes; and a capability an agent invokes by name, before re-running any appending job.

Given up: the tool needs a contract, so it does nothing when the operator cannot say what the run produces, and writing one is a per-run step. Tier 2 and tier 3 lose records, and their archives are evidence rather than a restore path. The corrupting producer is untouched, so a repeated interruption hits the same class again. The self-test is not part of CI, so a regression in the script surfaces only when someone runs it or uses the skill. Pid-liveness semantics also differ by platform, which the Windows `ctypes` path carries as the platform-specific cost.
