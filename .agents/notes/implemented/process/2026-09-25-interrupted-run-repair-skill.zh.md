# Agent Note: 中断复跑修复技能

Status: implemented

[English](2026-09-25-interrupted-run-repair-skill.md) | 中文

## 问题

长跑作业一旦被中断，它追加写或整体重写的落盘产物会朝两个相反方向坏掉，而单纯复跑对两者都无效。读方无法解析的残留会让每一次重试都在同一段字节上失败，产物永远无法完成；而读方能容忍的残留会被当成成功，于是半截记录、零字节完成标记、或被静默重置为空 JSON 的清单都能挺过复跑，把损伤藏下来。

区分这两类所需的判断——哪种字节形态让文件再也读不动、哪种会骗过完成检查、哪些修法会丢信息——先前只存在于各项目里，是在对外部流水线做审查时读生产者代码得出的：一个按拍追加样本的调度 tick、一个独立聚合的收盘任务、一把单写者锁、以及一个只用"存在"表示"已完成"的标记件。仓库里没有任何东西把那次阅读变成 agent 可执行的流程。

## 决策

`.agents/skills/dsh-interrupted-run-repair/` 落地这套流程与三个只用标准库的 Python 工具：`scripts/repair_interrupted_run.py`（含 `detect`（只读）、`repair`、`verify`、`selftest` 四个子命令）、`scripts/audit_interruption_hazards.py`（扫源码，找"会不断造出这类残留"的代码）、以及 `scripts/hazard_guard.py`（拿基线比对，只对新增报警）。修复工具的输入是一份**运行契约**——该次运行声称产出的产物清单，每项带 `kind`（`jsonl`、`csv`、`json`、`lock`、`text`）、可选的 `unique_key`（查重）、`columns`（CSV 字段数）、`role: completion-marker`（其"存在"即代表运行已完成的产物）、`required`（缺失即记为未完成）、`lease_seconds`（锁龄）。每项以 `path` 或 `glob` 指定，`glob` 在载入时按 root 展开，于是按日滚动的链条不必为明天新增的日子改契约；严格写法如 `day_????-??-??.jsonl` 能把同前缀的登记件排除在外。契约数据只用来指定文件，从不携带命令。

同一份契约同时充当审计的**产物图**：带 `--contract` 时，只要某个文件引用了声明产物，其中"截断后重写"就升级为 medium——这能抓到"甲文件写、乙文件读"的写方，而同文件规则看不见；同时抑制与任何声明产物无关的 advisory。在一个 284 文件、16 件声明产物的流水线上，medium 由 35 升到 61，advisory 由 605 降到 69：召回与降噪同时发生。门禁的身份 = `形态 + 级别 + 相对路径 + 归一化证据行 + 出现序号`：不含行号（行号漂移会把每次编辑都刷成假新增）、带出现序号（新加一处重复危害仍会被看见）、并含级别（advisory 升到 medium 是"变差了"，必须报）。门禁不绑定任何通道与退出码约定——`--notify-cmd` 从 stdin 收告警正文、`--min-severity` 定阈值、`--exit-code-new` 让调用方沿用自己调度器的码——因为那些是部署选择，不是检测逻辑。**扫不到任何文件时退出码是 2，而不是报"干净"**；`--update-baseline` 在这种情况下拒绝写基线：目录被改名后门禁否则会一直报干净，而一份空基线会把"让后续回归可见"的那些身份一起抹掉。`--allow-empty` 是显式的例外开关。

审计工具用 AST（而非正则）匹配六种形态：追加型文件被整体解析、坏件被替换成空文档、截断后重写、以 `exists()` 当完成判据、读-改-写在同一函数内无锁、`read_text()` 未带 `errors=`。**精度是设计约束，开发中为此收紧了三次**：升级为 medium 要求**同一文件**内读回该路径（`OUT` 这类名字在每个脚本里都是不同产物）；判定"静默重置"要求 `try` 体内确实读过持久输入（一次 RPC 失败后取默认值是另一种失效模式）；把失败如实记下的处理（`{"parse": "失败"}`）属披露而非重置。每条 high 在报出之前都逐条读码核对。

发现项分三类：**corruption**（阻断或伪造复跑）、**incompleteness**（只有重跑生产者才能清除）、**advisory**（供人判断，永不判失败）。修复按能清除该 corruption 的最窄档进行：第 1 档为丢了换行的完整记录补上换行、截掉被中断的尾段、把彻底不可用的文件挪开、清除可证明已死的锁；第 2 档（`--quarantine-lines`）保留可解析记录、归档其余；第 3 档（`--dedup`）按 `unique_key` 保留首条。每一步都在产物旁写一份归档并报出路径。

本技能的硬约束：越界即错（解析到 `--root` 之外的产物路径按契约错误退出，码 2）、不臆造内容、修复幂等、dry-run 不写盘、覆盖度记账（每份报告都写明声明产物实际检视了几件、在场几件、缺失几件，让干净判定可被证伪而不是沉默）、以及持有者仍活着的锁一律不清除（即使已过租期），除非显式 `--force-live-lock`。`--rerun "CMD"` 把生产者的命令、退出码与输出尾部与修复记录写进同一份报告，一次跑完整闭环；该命令来自操作者命令行，因此过期的契约无法触发执行。Windows 与 POSIX 的进程存活判定不同，Windows 路径经 `ctypes` 读取退出码。

本工具刻意不修的残留类别——两个并发写方的丢更新、读方吞掉解析错误后重置状态、二进制格式的截断、以及被丢弃记录的重建——连同理由记录在 `references/cases.md`，每个 fixture 对应的真实案例也在那里。

## 验证

`selftest` 在临时目录里构造 18 个用例，逐个断言完整闭环：detect 指出残留、repair 清除、生产者重跑、verify 报出完整且未受损。正例覆盖半截末行、完整记录丢换行、两条记录粘连、截断的 CSV 行、零字节完成标记、截断的 JSON 清单、死锁、重复记录、被切断的多字节尾部、以及跨多日的 glob 契约。未完成类用例覆盖必需 glob 匹配为空。负对照必须保持原样：干净产物、持有者仍活着的锁、完好目标旁的孤儿临时文件。护栏覆盖修复幂等、dry-run 不写盘且退出码如实反映当前档位能否清除、以及拒绝越出 root 的契约路径。

自测就是本能力的验收，按需运行；它没有接进 `pnpm` 门禁——那会把 Python 运行时要求塞进静态门禁集合。技能的 Markdown 由文档门禁覆盖。干净基线用例还会断言报告的覆盖率计数，避免什么都没读被误判为干净。`audit_interruption_hazards.py --selftest` 为扫描器断言镜像的一面：每种危害形态都必须在其 fixture 上触发、其**安全孪生**必须安静，契约必须把"引用声明产物的写方"升级为 medium，且远离声明产物的 advisory 必须被抑制。`hazard_guard.py --selftest` 断言门禁自身的契约：基线可写、已知项安静、新增项抵达调用方给定的退出码且告警正文进了通知命令的 stdin、行号漂移不算新增、新加一处重复危害算新增、阈值被遵守、以及"升级为声明产物"必须报出来——最后这条是在身份里补上"级别"之后才成立的，而正是自测把它抓出来的。两个扫描器还各自断言"响亮失败"这条路径：目标不存在、或扫不到任何 Python 文件时退出码为 2，而不是给出一次干净的审计结论。

## 曾考虑的替代方案

**逐个修生产者。** 输在时效，但对其中一类残留仍是正解：给读方的解析加护栏、把 `truncate` + `write` 换成原子改名、以及在输入损坏时 fail-loud 而不是重置状态，都能从根上防止损伤，而本技能修不了生产者。它救不了已经被中断的那次运行，且每个项目都要重做一遍；技能里明确写清哪些缺陷仍属生产者。

**只靠重跑生产者来修复。** 输在重跑既发现不了阻断它的残留，也看不见读方吞掉的那种残留：运行看起来成功，产物却仍是错的。本工具的职责是让重跑的起始状态可信，这正是契约与 detect 阶段存在的理由。

**做成带 verifier 与 CI 测试的包。** 输在它的消费者是操作者对其他项目文件的工作流，而不是 harness 运行时。仓库的包门禁——逐文件覆盖率、不变量、目录生成——会去管一个从不进入产品的工具；技能形态则让它在任何工作区都能被调用。

**把行级修复设为默认。** 输在丢记录是语义决定：分档让这份损失显式、需人显式开启，并写进报告，而不是藏在"干净"的判定里。

**引入第三方依赖。** 输在只用标准库才能让脚本在 agent 到得了的任何主机上跑起来，包括没装任何 Python 包的主机；`psutil` 与 `jsonschema` 各换来一点便利，代价是在不可改动的机器上加一道安装步骤。

## 后果

换来的：中断复跑这一场景有了确定的流程与证据链，外部流水线那次失败分析被固化成可运行的验收而不是散文；修复策略不会静默丢字节；以及一个能按名字被 agent 调用、在重跑任何追加型作业之前先跑的能力。

让出的：工具需要契约，操作者说不清这次运行该产出什么时它无能为力，而写契约是每次运行的一步。第 2、3 档会丢记录，其归档是证据而非回滚路径。造成损坏的生产者原样保留，因此同类中断再次发生仍会重现同类残留。自测不在 CI 内，脚本的回归只在有人运行它或使用技能时才暴露。进程存活语义还随平台而异，Windows 的 `ctypes` 路径把这部分平台成本单独担了下来。
